# Stable Android signing

Production package: `com.slashpromo.app`. Review/debug package: `com.slashpromo.app.debug`. Never uninstall an existing library installation to resolve a signature conflict.

Before provisioning, recover the existing production signing key if available and compare the SHA-256 certificate fingerprint against the installed APK with `apksigner verify --print-certs`. A certificate fingerprint is not the private key. A different signing key cannot update the old installation in place in the ordinary sideloading workflow.

Generate a new key only if the original cannot be recovered or a separate permanent installation is intended. Store the keystore in a restricted encrypted backup and configure protected GitHub environment secrets; never commit the keystore or passwords. The Gradle release build accepts SLASHPROMO_KEYSTORE_PATH, SLASHPROMO_KEYSTORE_PASSWORD, SLASHPROMO_KEY_ALIAS and SLASHPROMO_KEY_PASSWORD. All four are required together. Debug builds remain isolated and are not permanent releases.

Before distributing any release, check APK package ID, signing certificate SHA-256 and version code against the intended installed app. Verify the signature using apksigner. If the previous key is unavailable, preserve the original application and transfer a lawfully obtained source PDF into the new app once; app-private data cannot be directly copied between independently signed apps without a supported export mechanism. Book and index must never enter the repository or public build artifacts. Test offline search and data retention through two successive signed updates before relying on the release for clinical records.

## Existing canonical release workflow
The repository already has `.github/workflows/android-release-candidate.yml`, restricted to main and manual dispatch, using the `android-release` environment, secrets ANDROID_KEYSTORE_BASE64, ANDROID_STORE_PASSWORD, ANDROID_KEY_PASSWORD, and alias `slashpromo`. Reuse this workflow and existing key. It signs the unsigned APK with apksigner, verifies the certificate, and compares the fingerprint with the approved website association. No new secrets are needed. The optional Gradle signing configuration is for controlled local builds only; do not set those environment variables in the canonical workflow. Review/debug installations have a different package ID and cannot be updated by the production APK. Preserve their local library until a one-time import into the production app is verified.
